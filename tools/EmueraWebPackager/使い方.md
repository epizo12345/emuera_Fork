# Emuera Web Packager — 利用者向け

Emueraゲームフォルダから、ブラウザ用Web packageを作ります。Windows `Emuera.exe`をWebへコピーするツールではありません。入力フォルダは読み取りのみで、出力先へWeb Runtimeとpackageを生成します。

配布用PackagerはGitHub Releasesからruntime-template付きZIPとして入手する方針です。EXE単体では動作に必要なRuntime templateがなく、ZIP全体が必要です。ShinEraや他のゲームデータは添付されません。利用者自身が手元のゲームフォルダをPackagerで別途選択してください。公開済み1.0.7は[GitHub Release](https://github.com/epizo12345/emuera_Fork/releases/tag/web-packager-v1.0.7)から入手してください。公開済み[1.0.4 Release](https://github.com/epizo12345/emuera_Fork/releases/tag/web-packager-v1.0.4)と旧版は保持しています。

1.0.9の`EmueraWebPackager-1.0.9-win-x64.zip`を保存し、`SHA256SUMS.txt`でZIPのSHA-256を確認してから展開してください。展開先の`EmueraWebPackager.exe`を起動し、手元のゲームフォルダを選択します。版とチェックサムは同じ配布一式の情報で確認してください。Releaseの添付はツールZIPとチェックサムです。

## 手順

1. `EmueraWebPackager.exe`を起動します。
2. ERB/CSVのあるゲームフォルダ、またはその`Data`フォルダを選びます。
3. 新しい出力先を選び、必要ならitch.io用ZIPを有効にします。
4. 「Web版を作成」を実行し、完了表示を確認します。
5. 出力先の`index.html`をweb serverで開いて確認します。配布する場合はWeb出力一式、または生成したitch ZIPを使います。

初回選択後、Packagerは入力file snapshotを読み、追加・変更・削除を次回生成時に比較します。既存のWeb出力がPackager所有のものなら前版をbackupして置換できます。Packagerが作成したと確認できない出力は上書きしません。別の名前または空の出力先を選んでください。

## データ・保存の注意

- 手作業で変更したERB、CSV、画像もその現在bytesをpackage化できます。既知releaseのSHA一致は要求しません。
- `.sav`と`Data/sav`は配布packageへ含めません。ユーザーの通常saveはブラウザのIndexedDBに保存され、export/importはゲーム画面の保存管理を使います。
- 配布前に生成されたmanifestとpackage検証の完了を確認してください。
- Runtime template、ゲームデータ、セーブを一緒に再配布する権利はそれぞれの配布条件に従います。
- 生成Webの`LICENSE.md`、`licenses/`、`fonts/DotGothic16-OFL.txt`はエンジン・依存・フォントの通知です。配布時に保持してください。これらを同梱してもゲーム・画像・口上の再配布許諾を確認したことにはなりません。

## Preview

PreviewはこのPackagerが起動したlocalhost serverだけを対象にします。Preview停止はPackager自身が開いたlistenerへだけ作用します。既に他のアプリが使っているserverや通常ブラウザのprocessは停止しません。

マクロ実行中は画面上部の赤い「マクロ停止」で残り入力を破棄できます。通常のメッセージ送り停止とは別の操作です。停止後はゲームが安全な入力待ちへ進んだ時点で通常操作を続けてください。有限マクロは戦闘結果等の通常入力待ちで終了することもあります。

正常QUIT後は終了案内が出ます。保存が成功して完了した後に上部の「タイトルに戻る」を使えます。セーブは自動ロードせず、タイトルのLOAD GAMEから選択してください。

1.0.9の論理描画領域は1512×864pxです。小さいブラウザでも論理解像度を削らず、ゲーム枠を一様に縮小します。NGOイベントの上端約2行の見切れは既知の許容制約です。NGOの表示復帰は実ゲーム確認済みですが、後続進行全体は未確認です。


## Fキーとmacro.txt

- ゲームのタブがアクティブでページ／ゲーム入力へフォーカスがある間、F1～F12で選択グループのマクロを入力欄へ呼び出し、Shift＋F1～F12で非空の入力内容を登録します。Ctrl＋0～9で10グループを切り替えます。通常INPUTでは呼出後にEnterで実行します。ONEINPUT／AnyKey、ゲーム側キー入力待ちでは実機の入力契約が優先されます。
- ブラウザがFキーやCtrl＋数字を使う場合は、上部「マクロ操作」からグループ選択・呼出・登録を行えます。設定や編集欄、IME変換中、別タブには誤発火しない設計です。全ブラウザ／OS IME／itchでの動作は保証していません。
- 「macro.txtを読み込む」は全内容の検証とプレビュー後、確認して全10グループ・120スロットを置換します。未指定スロットは空、未指定グループ名は初期名。選択中グループは維持し、取消・不正・保存失敗では既存の登録を維持します。上限1MiB、不正行・重複・範囲外は全体拒否です。
- 「macro.txtを書き出す」は実機形式のCP932／BOMなし／CRLFでダウンロードします。CP932に表現できない内容、往復で別文字になる内容、改行等は拒否し、黙って?に置換しません。読込・書出だけでは実行しません。
- 通常登録はブラウザのlocalStorageへ自動保存し、origin・gameId・profileIdごとに分かれます。失敗時は未保存を表示します。ブラウザ間や公開先の移動にはmacro.txtの書出・読込を使えます。
- **セーブデータの書き出しにはマクロは含まれません。** セーブ管理とは別にmacro.txtを保存してください。個人macro.txt・セーブ・登録内容を配布物へ含めないでください。Packagerの既存入力収集はData/macro.txtを含め得るため、配布用ゲーム入力には個人ファイルを置かないでください。


## キャラdatと1.0.9の注意

- 通常セーブ／globalとキャラdatは別の保存対象です。通常セーブの書き出しにdatやmacroは含まれません。必要なものを各パネルから書き出してください。
- 保存先はorigin・gameId・profileIdごと。DB schema2へ更新した同じoriginを、旧schema1のWeb版で開くとVersionErrorになる場合があります。旧版の確認は別origin、または別のブラウザプロファイルで行ってください。URLの ?profile を変えるだけでは、旧版とのIndexedDB形式の互換問題を回避できません。同一originではDB名が共通で、profileIdは保存レコードの区分です。更新前に必要なファイルをバックアップしてください。
- HTML履歴は画像／図形等の検証済み範囲のみ。Group/DIV/Island、特殊寸法などの完全再構成は未対応・保留です。
- surface下端の1px背景帯に微小なRGB差が残ります。文字領域の安定と画面全体の完全一致は区別します。
- ユーザー受入は今回環境の冬眠dat・入力/HTML・文字上端・ダンジョン移動。全ブラウザ・DPR/zoom・長時間動作を保証しません。NGO上端約2行の許容済み見切れ、GDRAWGWITHMASK等の残件も維持。
- キャラdatはNative binary形式。Web資源上限は64MiB/ファイル、256キャラ、起動時4096ファイル/512MiB、portable leaf200文字。同期式関数内のSAVECHARAは安全に中断できないため保存前に拒否します。
- 配布入力には個人macro.txt、セーブ、キャラdat、ログを置かないでください。Packagerがすべて自動除外する保証はありません。利用権のあるクリーンな配布用コピーを用意します。
