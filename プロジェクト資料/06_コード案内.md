# Emuera.NET 高速・互換版 コード案内

最終更新: 2026-07-31

この文書は、プログラムに詳しくなくても「どの修正が、どのファイルで、何をしているか」を追えるようにする入口である。

## 1. 一番簡単な探し方

変更箇所の説明コメントには、すべて次の形の目印を付けてある。

```text
[Emuera改修:WARN-01]
[Emuera改修:START-01]
[Emuera改修:MACRO-01]
```

Visual StudioやVS Codeの「フォルダー内を検索」で `Emuera改修:` を検索すれば、説明付きの変更箇所だけを一覧表示できる。

コマンドで探す場合:

```powershell
rg -n "Emuera改修:" Program.cs Emuera.csproj Runtime UI "Emuera以外(開発補助ツールなど)"
```

特定機能だけなら、たとえば `Emuera改修:MACRO` や `Emuera改修:MOUSE` で検索する。

### .NET 10と単一EXEの構成を追う

[Emuera.csproj](../Emuera.csproj) の先頭にある`BUILD-02`と`BUILD-03`を読む。

```text
Windows 10 Version 2004以降を対象にする
        ↓
SkiaSharp 4.150.1の.NET 10向け部品を選ぶ
        ↓
Windows API全体の大きな.NET投影DLLは自動追加しない
        ↓
SkiaSharpが必要とするWinRT.Runtime 2.2.0だけを参照する
        ↓
発行対象へ明示的に戻して単一EXEへ格納する
```

`BUILD-03`の最後のTargetは、ゲーム起動後に動くC#処理ではない。EXEを作るときだけMSBuildが実行し、
パッケージ名とDLL名が一致する`WinRT.Runtime.dll`だけを発行一覧へ戻す。

参照:

- [.NETの単一ファイル配置](https://learn.microsoft.com/dotnet/core/deploying/single-file/overview)
- [Microsoft.Windows.CsWinRT 2.2.0](https://www.nuget.org/packages/Microsoft.Windows.CsWinRT/2.2.0)

## 3. 起動時の偽警告修正を追う

おすすめの順番:

1. [LabelDictionary.cs](../Runtime/Script/Data/LabelDictionary.cs) の `WARN-01`
2. [ErbLoader.cs](../Runtime/Script/Loader/ErbLoader.cs) の `WARN-06` と `START-01`～`START-03`
3. [Process.cs](../Runtime/Script/Process.cs) の `WARN-04`
4. [ParserMediator.cs](../Runtime/Script/Data/ParserMediator.cs) の `WARN-02`
5. [LogicalLineParser.cs](../Runtime/Script/Parser/LogicalLineParser.cs) の `WARN-03`
6. [VariableLocal.cs](../Runtime/Script/Statements/Variable/VariableLocal.cs) の `WARN-05`

全体の流れ:

```text
複数のERBファイルを同時に読む
        ↓
各スレッドがラベルや変数を登録する
        ↓
並列対応Dictionaryとlockで登録の衝突を防ぐ
        ↓
解析中の行番号はスレッドごとに分ける
        ↓
警告は並列対応Queueへ集める
        ↓
解析終了後に画面へ順番に表示する
```

この修正は警告を非表示にするものではない。正しいERBエラーは従来どおり報告する。

## 4. 起動高速化を追う

おすすめの順番:

1. [Preload.cs](../Runtime/Utils/Preload.cs) の `START-01`
2. [ErbLoader.cs](../Runtime/Script/Loader/ErbLoader.cs) の `START-01`～`START-03`
3. [Rename.cs](../Runtime/Utils/Rename.cs) の `START-05`
4. [EmueraConsole.cs](../UI/Game/EmueraConsole.cs) の `START-06`
5. [EmueraConsole.Print.cs](../UI/Game/EmueraConsole.Print.cs) の `START-06`

役割を簡単に言うと次のとおり。

- `Preload`: ERB・ERH・CSVを先にメモリへ読む
- `ErbLoader`: ERBのラベルと関数を解析する
- `Rename`: `[[名前]]` の置換を行う
- `EmueraConsole`: 読込中・タイトル画面の表示を担当する

`START-04` は強制GCの比較試験用コードで、通常版では無効。採用した起動高速化ではない。

## 5. マクロ高速化を追う

描画集約の中心ファイルは [EmueraConsole.cs](../UI/Game/EmueraConsole.cs)。`MACRO-01`、`MACRO-02`、`MACRO-03` の順に読む。

```text
マクロを複数入力へ展開
        ↓
batchingMacroDisplay = true
        ↓
各入力・ERB・文字列・表示行は全部処理
        ↓
Windowsイベントも入力ごとに処理
        ↓
実画面の更新だけ最大30 FPSに制限
        ↓
終了時にRefreshStrings(true)で最終画面を必ず描く
```

重要なのは、`batchingMacroDisplay` が「ゲーム処理を止めるスイッチ」ではなく「実ウィンドウの描画をまとめる目印」だという点。

表示行追加の計測は [EmueraConsole.Print.cs](../UI/Game/EmueraConsole.Print.cs)、文字幅の計測は [StringMeasure.cs](../UI/Game/StringMeasure.cs)、文字列生成の計測は [StrForm.cs](../Runtime/Script/Data/StrForm.cs) にある。

ERB処理側の追加高速化は、次の順で読む。

1. [VariableTerm.cs](../Runtime/Script/Statements/Variable/VariableTerm.cs) の `MACRO-04`: 添字を確定した一時参照を貸し出し、処理後に回収する本体
2. [Creator.Method.cs](../Runtime/Script/Statements/Function/Creator.Method.cs) の `MACRO-04`: `MATCH` / `CMATCH` が検索中だけ借りる箇所
3. [Instraction.Child.cs](../Runtime/Script/Statements/Instraction.Child.cs) の `MACRO-05`: `VARSET` / `CVARSET` が一括代入中だけ借りる箇所

```text
MATCHなどが配列を使う
        ↓
VariableTermから「添字確定済み参照」を借りる
        ↓
検索・一括代入・引数評価は従来どおり行う
        ↓
usingの終端で必ず返す
        ↓
次の呼び出しが同じ小さな入れ物を再利用する
```

貸出中の物はプールから外れるため、再帰関数の内側は別の物を借りる。整数用と文字列用も別々である。これは変数値をキャッシュする仕組みではなく、添字を一時的に写す入れ物だけを再利用する仕組みなので、ERB変更後も古い値は残らない。

[StrForm.cs](../Runtime/Script/Data/StrForm.cs) の `MACRO-06` は、埋め込み式が1個だけの整形文字列を扱う短経路である。

```text
前の固定文字 + {埋め込み式1個} + 後ろの固定文字
        ↓
式を従来と同じ場所で1回だけ評価
        ↓
汎用作業バッファへ全体を写さず、最大3個の文字列を直接連結
```

前後が空なら評価結果をそのまま返す。C#の文字列は後から書き換えられないため安全で、ERB関数・乱数の評価順も変わらない。埋め込みが複数なら従来の汎用処理を使う。

## 6. サイドボタンを追う

おすすめの順番:

1. [JSONConfigData.cs](../Runtime/Config/JSON/JSONConfigData.cs) の `MOUSE-01`: 検索する文言の初期値
2. [MainWindow.cs](../UI/Framework/Forms/MainWindow.cs) の `MOUSE-01`: XButton1/XButton2を受け取る
3. [EmueraConsole.cs](../UI/Game/EmueraConsole.cs) の `MOUSE-02`: 通常行・入れ子HTML・HTML Islandから表示文または内部入力値を探す

```text
マウスXButton1を押す
        ↓
設定から「前のページ|1007|PREV」などの候補を取得
        ↓
現在有効な通常行、入れ子HTML、HTML Islandを再帰検索
        ↓
表示文の部分一致、またはHTMLボタン内部入力値の完全一致を確認
        ↓
見つかったボタンの入力値を取得
        ↓
通常クリックと同じ入力処理へ渡す
```

対象候補に合う表示文・内部入力値のない画面では何もしない。ゲームのページ番号をEmueraが直接変更しているわけではない。

## 7. 大量ログの表示高速化を追う

おすすめの順番:

1. [ClipBoardDialog.Designer.cs](../UI/Framework/Forms/ClipBoardDialog.Designer.cs) の `CLIPBOARD-01`: 表示欄を`RichTextBox`へ変更
2. [ClipBoardDialog.cs](../UI/Framework/Forms/ClipBoardDialog.cs) の `CLIPBOARD-01`: ログ設定中だけ再描画を停止
3. [MainWindow.cs](../UI/Framework/Forms/MainWindow.cs) の `CLIPBOARD-02`: Ctrl+Cとメニューの両経路で閉じた画面を破棄

```text
Ctrl+Cまたはメニューからログ画面を開く
        ↓
表示欄の途中再描画だけを止める
        ↓
ゲームの全ログを従来どおり取得して設定する
        ↓
再描画を再開して完成した内容を表示する
        ↓
画面を閉じたらusingで画面部品と保持中ログを破棄する
```

`WM_SETREDRAW`はログ生成や文字列設定を飛ばす命令ではなく、Windowsへ「設定中はまだ描かなくてよい」と伝える命令である。
`try` / `finally`により、途中で例外が起きても再描画は必ず戻る。

`MainWindow.cs`には入口が2つある。105行付近は選択文字列のない状態でCtrl+CまたはCtrl+Insertを押した場合、
721行付近はメニューの「ログをクリップボードにコピー」を選んだ場合である。どちらも同じ`ClipBoardDialog`を開くため、
閉じた後の破棄も両方へ入れている。

## 8. 性能計測を追う

入口は次の順番。

1. [Emuera.csproj](../Emuera.csproj) の `MEASURE-01`
2. [Program.cs](../Program.cs) の `MEASURE-01` と `TOOLS-01`
3. [PerformanceMetrics.cs](../Runtime/Utils/PerformanceMetrics.cs) の `MEASURE-01`

通常版では `EnablePerformanceMetrics=false`。計測版だけ次のようにビルドする。

```powershell
dotnet publish .\Emuera.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=true -p:EnablePerformanceMetrics=true -o .\作業用\計測版
```

状態比較の流れ:

- [VariableEvaluator.cs](../Runtime/Script/Statements/Variable/VariableEvaluator.cs) の `MEASURE-03`: 変数をメモリ上へセーブ形式で書く
- [EraBinaryDataWriter.cs](../Runtime/Utils/EraBinaryDataWriter.cs) の `MEASURE-03`: ファイル以外のMemoryStreamにも書けるようにする
- [EmueraConsole.Print.cs](../UI/Game/EmueraConsole.Print.cs) の `MEASURE-05`: 最終表示をハッシュ化する
- [VariableEvaluator.cs](../Runtime/Script/Statements/Variable/VariableEvaluator.cs) の `MEASURE-04`: 乱数呼出の順序を記録する

これらは比較試験用で、通常プレイのセーブを作成・変更しない。

## 10. 初心者向け用語集

| 用語 | このプロジェクトでの意味 |
|---|---|
| ERB | ゲームの処理が書かれたスクリプト |
| ERH | 変数や定義を書いたヘッダースクリプト |
| CSV | キャラクターやゲームデータの表 |
| スレッド | 複数の処理を同時に進める「作業員」のようなもの |
| Dictionary | 名前からデータを素早く探す入れ物 |
| ConcurrentDictionary | 複数の作業員が同時に使っても壊れにくいDictionary |
| lock | 一部分を一時的に一人だけが操作する仕組み |
| Queue | 入ってきた順に取り出す待ち行列 |
| Interlocked | 同時に加算・書込みしても取りこぼさない仕組み |
| FPS | 1秒間に画面を何回更新するか |
| GC | 使い終わったメモリを.NETが回収する仕組み |
| 再描画 | Windowsが画面の見た目を作り直す処理。内容の計算や保存とは別 |
| `using` | 使い終わった画面やファイルなどを、処理終了時に確実に破棄する書き方 |
| プール | 使い終わった小さな入れ物を、次回のため少数だけ保管する場所 |
| リース（貸出） | 借りている間は他の処理へ渡さず、終了時に必ず返す使い方 |
| ハッシュ | 大きなデータが同じか確認するための短い指紋 |
| SHA-256 | このプロジェクトで使っているハッシュ方式 |
| コンパイル | C#のソースを実行できるEXEへ変換すること |
| 条件付きコンパイル | 通常版と計測版で、含めるコードを切り替える仕組み |

## 11. 読むときの注意

- コメントは「なぜ変更したか」を説明する。正確な動作は直後のコードが基準
- コメントとコードが食い違った場合は、コード修正と同時にコメント・本書・仕様書も更新する
- `MEASURE` と `TOOLS` は検証を支える変更で、プレイヤー向け機能そのものではない
- `START-04` は不採用比較機能を無効状態で残したもの。通常版で有効にしない
- 17～29番の不採用実験コードは現行ソースに残していない
