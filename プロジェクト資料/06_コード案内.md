最終更新: 2026-09-24

## 1. 一番簡単な探し方

変更箇所の説明コメントには、すべて次の形の目印を付けてある。

```text
[Emuera改修:WARN-01]
[Emuera改修:START-01]
[Emuera改修:MACRO-01]
```

Visual StudioやVS Codeの「フォルダー内を検索」で `Emuera改修:` を検索すれば、説明付きの変更箇所だけを一覧表示できる。

コマンドで探す場合:

```powershell
rg -n "Emuera改修:" Program.cs Emuera.csproj Runtime UI "Emuera以外(開発補助ツールなど)"
```

特定機能だけなら、たとえば `Emuera改修:MACRO` や `Emuera改修:MOUSE` で検索する。

### .NET 10と単一EXEの構成を追う

[Emuera.csproj](../Emuera.csproj) の先頭にある`BUILD-02`と`BUILD-03`を読む。

```text
Windows 10 Version 2004以降を対象にする
        ↓
SkiaSharp 4.150.1の.NET 10向け部品を選ぶ
        ↓
Windows API全体の大きな.NET投影DLLは自動追加しない
        ↓
SkiaSharpが必要とするWinRT.Runtime 2.2.0だけを参照する
        ↓
発行対象へ明示的に戻して単一EXEへ格納する
```

`BUILD-03`の最後のTargetは、ゲーム起動後に動くC#処理ではない。EXEを作るときだけMSBuildが実行し、
パッケージ名とDLL名が一致する`WinRT.Runtime.dll`だけを発行一覧へ戻す。

参照:

- [.NETの単一ファイル配置](https://learn.microsoft.com/dotnet/core/deploying/single-file/overview)
- [Microsoft.Windows.CsWinRT 2.2.0](https://www.nuget.org/packages/Microsoft.Windows.CsWinRT/2.2.0)

## 5. マクロ高速化を追う

描画集約の中心ファイルは [EmueraConsole.cs](../UI/Game/EmueraConsole.cs)。`MACRO-01`、`MACRO-02`、`MACRO-03` の順に読む。

```text
マクロを複数入力へ展開
        ↓
batchingMacroDisplay = true
        ↓
各入力・ERB・文字列・表示行は全部処理
        ↓
Windowsイベントも入力ごとに処理
        ↓
実画面の更新だけ最大30 FPSに制限
        ↓
終了時にRefreshStrings(true)で最終画面を必ず描く
```

重要なのは、`batchingMacroDisplay` が「ゲーム処理を止めるスイッチ」ではなく「実ウィンドウの描画をまとめる目印」だという点。

表示行追加の計測は [EmueraConsole.Print.cs](../UI/Game/EmueraConsole.Print.cs)、文字幅の計測は [StringMeasure.cs](../UI/Game/StringMeasure.cs)、文字列生成の計測は [StrForm.cs](../Runtime/Script/Data/StrForm.cs) にある。

ERB処理側の追加高速化は、次の順で読む。

1. [VariableTerm.cs](../Runtime/Script/Statements/Variable/VariableTerm.cs) の `MACRO-04`: 添字を確定した一時参照を貸し出し、処理後に回収する本体
2. [Creator.Method.cs](../Runtime/Script/Statements/Function/Creator.Method.cs) の `MACRO-04`: `MATCH` / `CMATCH` が検索中だけ借りる箇所
3. [Instraction.Child.cs](../Runtime/Script/Statements/Instraction.Child.cs) の `MACRO-05`: `VARSET` / `CVARSET` が一括代入中だけ借りる箇所

```text
MATCHなどが配列を使う
        ↓
VariableTermから「添字確定済み参照」を借りる
        ↓
検索・一括代入・引数評価は従来どおり行う
        ↓
usingの終端で必ず返す
        ↓
次の呼び出しが同じ小さな入れ物を再利用する
```

貸出中の物はプールから外れるため、再帰関数の内側は別の物を借りる。整数用と文字列用も別々である。これは変数値をキャッシュする仕組みではなく、添字を一時的に写す入れ物だけを再利用する仕組みなので、ERB変更後も古い値は残らない。

[StrForm.cs](../Runtime/Script/Data/StrForm.cs) の `MACRO-06` は、埋め込み式が1個だけの整形文字列を扱う短経路である。

```text
前の固定文字 + {埋め込み式1個} + 後ろの固定文字
        ↓
式を従来と同じ場所で1回だけ評価
        ↓
汎用作業バッファへ全体を写さず、最大3個の文字列を直接連結
```

前後が空なら評価結果をそのまま返す。C#の文字列は後から書き換えられないため安全で、ERB関数・乱数の評価順も変わらない。埋め込みが複数なら従来の汎用処理を使う。

## 8. HTML/FONT fast pathを追う

入口は[HtmlManager.cs](../UI/Game/HtmlManager.cs)の`HTML-01`、`Html2DisplayLine`である。

```text
入力全体をstrict color-only FONT文法で1回検証
        ↓
適格ならConsoleStyledString / ConsoleButtonStringを生成
        ↓
PrintStringBuffer.ButtonsToDisplayLinesへ渡してreturn
        ↓
```

対象は通常テキストとsingle quoteの`#RRGGBB`だけで、ASCII spaceの許可位置も限定する。FONT以外のタグ、nested FONT、追加属性、entity、改行・制御文字、surrogate、case variant、double quote、unquoted color、named colorは対象外である。`HTML-01`は診断shadow処理やallocation計測を含まない。

C2 v2のeligible 7,938/7,938、C3 smoke、C5のeligible 5,538/5,538を確認済み。C5の約80.839%削減はstrict対象HTML経路限定であり、ゲーム全体の改善率ではない。

## 9. Graphics / native lifetimeを追う

`GraphicsImage.cs`では、GraphicsImageがBrush/Penのownerであり、Draw側はfield-owned objectを解放しない。DIVの`BorderStyle`は`SKPaint`ではなく色と線幅の値を保持する。

Phase 14N2では、ColorMatrix描画のtemporary `SKColorFilter`、`GFillPolygon`のmethod-local `SKPath`、`_font == null`時だけ生成するtemporary `SKFont`を描画スコープ内でDisposeする。`_font != null`のborrowed/cached fontやFontFactoryのownerは解放しない。`ASpriteSingle`のnegative flip用`SKBitmap`もnormal / color-matrix双方で描画後にDisposeする。flip座標、sampling、pixel semanticsは変更していない。

## 11. セーブデータ書き込み高速化を追う

対象は[EraBinaryDataWriter.cs](../Runtime/Utils/EraBinaryDataWriter.cs)である。セーブ中に、要素の大半が0である大きな整数配列を1つずつ調べる処理が時間を使っていた。0が続く範囲をまとめて検索し、保存時の探索を効率化した。

- A1（`SAVE-01`）は1次元・2次元整数配列が対象
- A2（`SAVE-02`）は3次元整数配列が対象。最右次元を行として走査する
- セーブ形式、読み込み側（reader）、versionは変更していない
- 旧処理と新処理の出力をbyte単位で比較し、さらに最終`save401.sav`のSHA-256一致で互換性を確認した

### 1次元・2次元の保存を読む

`writeData(long[])`と`writeData(long[,])`にある`SAVE-01`を読む。`ReadOnlySpan<long>`と`IndexOfAnyExcept(0L)`で次の0以外の要素を探し、既存の`Zero` / `ZeroA1` / `EoA1` / `EoD`の記録規則を保つ。

### 3次元の保存を読む

`writeData(long[,,])`にある`SAVE-02`を読む。各行を最右次元に沿って走査する。最右次元の長さが0の場合には先頭要素を参照しない。`Zero` / `ZeroA1` / `ZeroA2` / `EoA1` / `EoA2` / `EoD`の意味は従来どおりである。

## 12. CDFLAGメモリ削減を追う

入り口は[CharacterData.cs](../Runtime/Script/Statements/Variable/CharacterData.cs)の`MEM-C1W`である。CDFLAGはキャラクタごとに大きな2次元整数配列を持つが、代表save219で5 / 100 / 450人のすべてが全0だった。そのため、全0の間は「まだ配列を作っていない」状態で保持する。

```text
全0のCDFLAG
        ↓
実配列を作らず、論理的に0を返す
        ↓
非0の書き込み、またはraw arrayが必要になった時だけ実配列を作る
```

- materializeはCDFLAG専用`EnsureCFlagBacking()`に集約し、他の2次元配列は変更していない
- 一度作った実配列は、全0に戻っても同じinstanceを保持する
- [VariableToken.cs](../Runtime/Script/Statements/Variable/VariableToken.cs)はread / write / plus / bulk / raw arrayをnull-awareに扱う
- [EraBinaryDataReader.cs](../Runtime/Utils/EraBinaryDataReader.cs)と[EraBinaryDataWriter.cs](../Runtime/Utils/EraBinaryDataWriter.cs)のCDFLAG専用経路で、配列を作らず既存セーブを読み書きする
- セーブ形式・versionは変更せず、N100後`save401.sav`のSHA-256完全一致を確認した
- save219ロード直後のCDFLAG payload削減は5人2.06 MiB、100人41.20 MiB、450人185.39 MiB

## 13. SET左辺の保持を追う

入り口は[WordCollection.cs](../Runtime/Script/Parser/WordCollection.cs)と[LogicalLine.cs](../Runtime/Script/Statements/LogicalLine.cs)の`MEM-M3A`である。SET左辺は初回の引数解析までだけ必要だが、従来はその間`WordCollection`を保持していた。M3Aは同じ`Word`参照と順序だけをexact-size配列へ記録し、初回parse時だけ既存parser向けの一時`WordCollection`へ戻す。

```text
SET左辺を字句解析
        ↓
WordCollection
        ↓ 凍結（同じWord参照・順序）
exact-size Word[] snapshot
        ↓ InstructionLineが初回parseまで保持
一時WordCollectionへ復元
        ↓
snapshot slotを解放
```

`Word`をcloneせず、`Collection()`や`Pointer()`を呼ばないため、compact collectionのlinked昇格やpointer変更は起こらない。直接対象型のshallow保持量23.90 MiB減少は、この入れ物に限った値でありゲーム全体のメモリ削減量ではない。

## 14. 定数添字の変数参照を追う

入り口は[VariableTerm.cs](../Runtime/Script/Statements/Variable/VariableTerm.cs)と[VariableToken.cs](../Runtime/Script/Statements/Variable/VariableToken.cs)の`MEM-M4A`である。定数添字の変数参照は長く残ることがあるが、添字が1個や2個なら従来の3要素配列には未使用slotがあった。M4Aは必要な長さだけの配列を共有する。

```text
定数添字を確定
        ↓
exact-size transporter（例: [5]、[5, 10]）
        ↓
FixedVariableTermが共有
        ↓
欠けた添字の読取りは論理0
        ↓
欠けた添字への書込み時だけlong[3]へcopy-on-write
```

共有元配列は書き換えない。通常の短命参照用poolと`Reset`は従来どおり3要素配列を使う。M3AとM4Aは測定対象が異なるため、各効果を単一のメモリ削減量として合算しない。

- `setting.json`はゲーム作者・バリアント作者の推奨値、`setting_user.json`はプレイヤー個人の上書き値を保存する。
- `setting_user.json`にLazyERB blockがあれば、その内容全体がゲーム側を上書きする。フォルダを両側から合成せず、`有効=false`も明示的な上書きとして扱う。
- 「ゲーム推奨に戻す」はuser側blockを削除する操作。通常編集では、両ファイルの未知propertyとLazyERB object内の未知propertyも保持する。
- 設定画面の「起動」タブで推奨値かこのPC用設定を選ぶ。保存した変更は次回起動から反映する。
- `LazyErbPolicy.cs`が、絶対パス・`..`・ERB root・ERB外・個別ERBファイル・reparse pointを拒否する。Debug / Analysisと既存の危険ERB eager fallbackは維持する。
- `LazyErbDirectoryDialog.cs`はERB内のサブフォルダを動的に表示する。親を選ぶと子孫も対象表示になるが、保存するのは親パスだけ。子を個別選択した場合はその子だけを保存する。
- 親をユーザー操作で解除すると子孫も解除する。親ONのまま子を解除した場合は親だけ解除し、他の兄弟選択は保つ。子を個別にすべてONにしても親は自動ONにならない。
- checkbox上のnative double-clickだけを抑止し、フォルダ名上のdouble-clickによる展開・折りたたみは維持する。

## ダークモード切り替えを追う

設定値から起動時のテーマ適用まで、次の順で読む。

```text
ConfigCode.cs
  ↓
ConfigData.cs
  ↓
Config.cs
  ↓
Program.cs
  ↓
ConfigDialog.cs
```

`emuera.config`の「ダークモードを使用する」はboolで、既定値YESは従来のDark表示を維持する。起動時にYESならDark、NOならClassicを適用し、設定画面の「表示」タブで変更する。反映は再起動後で、ゲーム本文の色設定は対象外。現在は実装・実機確認済みで、正式配布版への反映作業中である。

回帰確認は [`ConfigRegressionTests`](<../Emuera以外(開発補助ツールなど)/ConfigRegressionTests/Program.cs)（`TOOLS-05`）で行う。

## 17. 初心者向け用語集

| 用語 | このプロジェクトでの意味 |
|---|---|
| ERB | ゲームの処理が書かれたスクリプト |
| ERH | 変数や定義を書いたヘッダースクリプト |
| CSV | キャラクターやゲームデータの表 |
| スレッド | 複数の処理を同時に進める「作業員」のようなもの |
| Dictionary | 名前からデータを素早く探す入れ物 |
| ConcurrentDictionary | 複数の作業員が同時に使っても壊れにくいDictionary |
| lock | 一部分を一時的に一人だけが操作する仕組み |
| Queue | 入ってきた順に取り出す待ち行列 |
| Interlocked | 同時に加算・書込みしても取りこぼさない仕組み |
| FPS | 1秒間に画面を何回更新するか |
| GC | 使い終わったメモリを.NETが回収する仕組み |
| 再描画 | Windowsが画面の見た目を作り直す処理。内容の計算や保存とは別 |
| `using` | 使い終わった画面やファイルなどを、処理終了時に確実に破棄する書き方 |
| プール | 使い終わった小さな入れ物を、次回のため少数だけ保管する場所 |
| リース（貸出） | 借りている間は他の処理へ渡さず、終了時に必ず返す使い方 |
| ハッシュ | 大きなデータが同じか確認するための短い指紋 |
| SHA-256 | このプロジェクトで使っているハッシュ方式 |
| コンパイル | C#のソースを実行できるEXEへ変換すること |
| 条件付きコンパイル | 通常版と計測版で、含めるコードを切り替える仕組み |

## 18. 読むときの注意

- コメントは「なぜ変更したか」を説明する。正確な動作は直後のコードが基準
- コメントとコードが食い違った場合は、コード修正と同時にコメント・本書・仕様書も更新する
- `MEASURE` と `TOOLS` は検証を支える変更で、プレイヤー向け機能そのものではない
- `START-04` は不採用比較機能を無効状態で残したもの。通常版で有効にしない
- 17～29番の不採用実験コードは現行ソースに残していない
