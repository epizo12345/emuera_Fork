# ビルド・配布手順

## 前提

.NET 10 SDKとWebAssembly AOTに必要なSDK/ワークロードを用意します。Web appは`Web/Emuera.Web/Emuera.Web.csproj`、Packagerは`tools/EmueraWebPackager/Gui/EmueraWebPackager.Gui.csproj`を使います。生成物は`artifacts/`へ置き、source treeや入力ゲームへ混ぜません。

## Web Runtime

通常Release（`<build-name>`は未使用の新しい名前に置き換え、既存出力へpublishしない）:

```powershell
dotnet restore Web/Emuera.Web/Emuera.Web.csproj --artifacts-path artifacts/Web/<build-name>
dotnet publish Web/Emuera.Web/Emuera.Web.csproj -c Release --no-restore --artifacts-path artifacts/Web/<build-name> -o artifacts/Web/<build-name>/publish
```

Clean AOT（Normalとは別の未使用名・出力を使う）:

```powershell
dotnet restore Web/Emuera.Web/Emuera.Web.csproj --artifacts-path artifacts/Web/<aot-name> -p:RunAOTCompilation=true
dotnet publish Web/Emuera.Web/Emuera.Web.csproj -c Release --no-restore --artifacts-path artifacts/Web/<aot-name> -p:RunAOTCompilation=true -p:EnableErbExecutionProfiler=false -o artifacts/Web/<aot-name>/publish
```

AOTで.NET native toolが非ASCII temporary pathに失敗する環境では、`TEMP`、`TMP`、`TMPDIR`、`DOTNET_CLI_HOME`、`APPDATA`だけをbuild process内のASCII pathへ設定し、終了時に元の環境値へ戻します。システム全体の環境変数は変更しません。詳しくは[保守・更新手順](10_保守・更新手順.md)。

## PackagerとRuntime template

PackagerのCore/GUI/Testsは`tools/EmueraWebPackager/`にあります。`tools/EmueraWebPackager/build.ps1`で一意な名前の隔離出力へfocused testsまたはWindows `win-x64` self-contained single-file publishを行えます。新しいRuntime templateはWeb publish出力から作り、選択ゲームのsave、report、fixture、過去artifactを含めず、Tests projectの`seal`コマンドで`.template-manifest.json`を再生成します。Packagerはtemplate file list/SHAを検証してからコピーします。

利用者はPackagerでゲームフォルダと出力先を選び、Web packageを作成します。必要ならitch ZIPも同時生成し、ローカルでrootとサブパスを試してから配布します。外部uploadはこの手順外です。
