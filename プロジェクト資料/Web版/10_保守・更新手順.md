# 保守・更新手順

## ゲーム更新

```text
ゲームデータ更新 → 必要なローカル修正 → Packagerで現行bytesをsnapshot
→ 差分確認 → Web package生成 → root/subpathでlocal test → itch ZIP確認
```

公式release SHAへの一致を要求しません。snapshotのSHAは入力・packageの整合性検証用です。ゲームsourceは原則変更せず、変更が必要な場合は利用者のgame copyで行い、原本や配布元を上書きしません。

## Web未対応命令

1. 実際のcurrent ERB callsiteと引数を確認する。
2. 現在のMAIN_OPT Native実装と既存描画・入力semanticsを読む。
3. 小型caseでNative/Webの違いを記録する。
4. Web backendの該当境界へ必要最小限実装し、focused regressionと実ゲーム経路を確認する。
5. 診断コードをproduction buildに含めず、Known Limitationsを更新する。

GAME ERBの変更でunsupported APIを隠さない。

## Build / release

NormalとClean AOTの手順は[ビルド・配布](06_ビルド・配布手順.md)、ゲーム入力とarchive条件は[パッケージ仕様](03_ゲームデータパッケージ仕様.md)を参照します。AOTでは`RunAOTCompilation=true`、`EnableErbExecutionProfiler=false`を明示し、fresh artifacts pathを使います。非ASCII temporary pathのnative tool問題に対しては process-scoped environmentだけを変更し、finallyで戻します。

公開前に候補source/package/runtime templateのhash、manifest/archive一致、sav除外、license、保存profileを照合します。Packagerによるsnapshot/updateはWeb保存領域を変更しないことを別に確認します。
