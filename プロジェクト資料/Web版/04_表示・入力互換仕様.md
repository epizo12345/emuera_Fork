# 表示・入力互換仕様

## 入力の境界

- Enter、文字キー、数値選択、HTMLボタン、右クリックは現在のRuntime要求に対応付けて送信する。
- イベントはsession generation、request ID、button generationを検証する。古い表示行は見えていても現在の入力要求を消費しない。
- `TWAIT`、`INPUTMOUSEKEY`、primitive、timed inputはそれぞれの要求種別・期限・結果形式を維持する。
- キー長押しはブラウザの物理`KeyboardEvent.repeat`をauthorityにする。独自repeat timerを重ねない。同一holdのone-input repeatだけをbusy区間で次要求へ最大1件保留し、WAIT/primitive/timed inputや別のtapを遅延させない。
- 右クリックはmessage-skipとして扱い、通常のマウス選択値へ変換しない。停止境界と次の要求への入力漏れを守る。

## 表示の境界

`BrowserConsole`は論理行と履歴を保持します。DOM windowingは末尾表示または可視範囲とoverscanだけをDOMへ投影する仕組みで、論理履歴の削除やRuntime memory上限ではありません。過去位置のscroll anchorは行IDと行内offsetで維持します。

HTML island、画像、文字、配置group、input activationは論理表示モデルから組み立てます。アニメーションrefreshは表示範囲の必要な画像を更新し、変化しないSpriteFを再encodeしません。画像更新通知は描画機会を示し、`requestAnimationFrame`を物理paint完了保証として扱いません。

## Graphicsと関数呼び出し

現行UX16-07では、確認済み範囲で`GSETBRUSH`、`GSETFONT`、`GDRAWTEXT`をWeb graphicsへ対応しています。SKImageは不変なので、文字描画は新しいsnapshotへ置換し、内容世代を進めてSpriteGのURLを失効させます。paintは画像が所有し、FontFactoryのfontは共有借用です。WASMでMS Gothicが解決できない場合は同梱DotGothic16へfallbackします。NativeとWebのfont rasterization一致は保証しません。

Web Runtimeに限り、静的に解決された1～32引数の再利用可能function callsiteは引数種別metadataをpackedに保持する経路があります。条件外はlegacy経路へ戻り、Windows Nativeの呼び出し経路は変更しません。
