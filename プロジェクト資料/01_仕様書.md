# Emuera.NET 高速・互換版 仕様書

最終更新: 2026-07-15  
状態: 最終通常版（採用済み）

## 1. 対象

- プロジェクト: Emuera.NET
- 基礎ソース: `alnatiyan/EmueraDotNet` の `BugFix_Test`
- 基礎コミット: `7b7dd3bf240eff4fdfc7094f4175de0e014532b7`
- 主な検証対象ゲーム: `eramegaten_p` / ShinEraTenseiP 0.5.9
- 主な検証セーブ: `Data/sav/save219.sav`
- セーブSHA-256: `EDA8CA49F405D8C61C1E2572FE1510F1218D0ABCA1502E0E46B21C7699E62A14`
- 実行環境: Windows x64 / .NET 9
- 通常版の配布形態: framework-dependent、単一EXE

この派生版の目的は、既存ゲームとの互換性を優先したまま、起動と大量入力マクロを高速化し、操作性を補うことである。

## 2. 最終採用した機能

### 2.1 起動時にまれに出る誤警告の抑止

#### 現象

同一ゲーム・同一ERBでも、起動ごとに次のような警告が不定期に発生していた。

- 現在の関数内に存在するラベルが「存在しない」と判定される
- 正しいERB関数の引数が「引数の書式が間違っている」と判定される
- 識別子やローカル変数が一時的に未定義と判定される

#### 原因と対策

ERBの並列読み込み・解析中に、ラベル辞書、警告キュー、ローカル変数辞書、解析中行などの共有状態が競合していた。次の対策を採用した。

- 共有辞書・集合・警告キューを並列アクセス可能な構造へ変更
- 同一ラベル配下のリスト操作を必要箇所で排他
- 解析中行を並列解析時はスレッドごとに保持
- ERBファイルに列挙順のインデックスを付け、後段で安定した順序に整列
- ラベル引数解析と関数解析を例外隔離し、並列処理終了時に解析状態を確実に解除
- 並列処理で使うカウンタを原子的に更新

正しい警告そのものを隠す機能ではない。競合で発生していた偽警告を防ぎ、本当に解釈できないERBは従来どおり報告する。

### 2.2 起動高速化

次の処理を採用している。

- CSV・ERH・ERBの事前読み込みを並列化
- ERBファイルの読み込み、ラベル引数解析、到達対象関数の解析を安全な範囲で並列化
- `[[...]]` を含まない大多数の行でRename用正規表現を実行しない高速経路
- 起動直後の不要な初期描画を抑制
- 通常版では計測機能をコンパイル時に無効化し、計測オーバーヘッドを除外

ERBキャッシュは採用していない。試作では初回・通常起動の総時間に安定した改善がなく、キャッシュ無効化と互換性管理の複雑さに見合わなかったためである。プレイヤーがキャッシュを手動削除する仕組みも存在しない。

### 2.3 マクロ高速化

既存のマクロ記法とゲーム処理は維持し、複数入力マクロの画面再描画だけをまとめる。

- マクロ展開後の入力が複数なら表示バッチ状態へ入る
- 各入力について、入力受け渡し、ERB実行、文字列生成、表示行追加は従来どおり行う
- 入力順、関数評価順、乱数消費順を変更しない
- `\e` のメッセージスキップ、`\n` の入力区切りを従来どおり処理する
- `WAIT`、`TWAIT`、入力待ち、右クリック相当、マクロ中断の意味を変えない
- マクロ中も入力ごとにUIイベントを処理し、ウィンドウの応答性と中断操作を維持する
- 複数入力マクロ中の実画面更新を最大30 FPSに制限する
- マクロ終了時は必ず強制描画し、最終表示を反映する

これは「ゲーム処理や途中出力を省略する」実装ではない。表示データは生成されるが、同じ短時間に連続するOnPaint・スクロール反映を集約する。

標準ベンチマーク記法は次のとおり。

| 用途 | マクロ |
|---|---|
| 動作確認 | `(H\e\nd\e\n)*10` |
| 短い性能比較 | `(H\e\nd\e\n)*100` |
| 通常比較 | `(H\e\nd\e\n)*1000` |
| 耐久試験 | `(H\e\nd\e\n)*5000` |

### 2.4 マウスのサイドボタンによるページ移動

ゲーム側ERBを変更せず、Emuera側で現在表示中の選択肢を検索して入力する。

- XButton1（一般的な「戻る」）: `前のページ`、`前ページ`、`1007`、`PREV` のいずれかに合う現在の選択肢
- XButton2（一般的な「進む」）: `次のページ`、`次ページ`、`後ろのページ`、`1009`、`NEXT` のいずれかに合う現在の選択肢
- 数値入力待ちでは数値ボタンだけを対象にする
- 過去ログをスクロール表示中は、誤操作防止のため最新行へ戻すだけでページ入力しない
- 現在世代のボタンに対象文言がなければ何もしない

検索文言は `setting_user.json` の次のプロパティで変更できる。`|` は候補区切り、空文字は無効を意味する。

```json
{
  "MouseXButton1ButtonText": "前のページ|前ページ|1007|PREV",
  "MouseXButton2ButtonText": "次のページ|次ページ|後ろのページ|1009|NEXT"
}
```

JSONは1行でも複数行でも同じ意味である。既存の最初の `{` の直後へ無理に文字を差し込まず、上の例の2項目を他の項目と同様にカンマ区切りで置けばよい。現在の `eramegaten_p/Data/setting_user.json` は読みやすい複数行形式へ整形済み。

実ファイルの日本語は `\u524D` のようなJSON標準のUnicodeエスケープで記録している。Shift-JISと誤判定するエディタで開いても文字化けせず、Emueraが読み込むと上の例と同じ日本語へ戻る。

表示文は候補を「含む」かで判定し、HTMLボタンの内部入力値は候補との完全一致で判定する。通常の表示行だけでなく、`div` の内側に入れ子になったHTMLボタンと、絶対配置用HTML Islandも再帰的に検索する。したがって `1007` / `1009` は調教画面のHTMLボタン、`PREV` / `NEXT` はショップ画面の表示文を対象にできる。英字は大文字小文字を区別しない。

既存の `setting_user.json` にこの項目がなくても初期値が使われるため、導入時の手編集は不要である。Emueraが設定を保存した際は新しい2項目がJSONへ追記されるが、既存の設定値は維持される。

画面によって効く・効かない差があるのは、ゲーム側のボタン表示文または内部入力値が上記候補に合うかどうかによる。ページ番号をEmueraが直接変更する方式にはしていない。

## 3. 互換性要件

最終通常版は次を必須条件とする。

- 既存セーブを変換なしで読み込める
- 新規ゲーム開始を要求しない
- ERB、ERH、CSV、画像を変更しない
- 既存のマクロ記法を維持する
- 入力の実行順序を変えない
- ERB関数の実行回数・評価順序を変えない
- 乱数の消費順序を変えない
- `WAIT`、`TWAIT`、入力待ち、右クリック、スキップの意味を変えない
- マクロの中断操作とウィンドウ応答性を維持する
- 途中表示データと終了時表示を生成する
- .NET 9がない環境ではランタイム導入を許容する
- ゲーム固有ファイルの自動書換えを行わない

## 4. 計測機能

通常版では性能計測は無効である。開発用ビルドだけ `EnablePerformanceMetrics=true` を指定すると、起動とマクロの内部区間をJSON Linesへ記録できる。

主な起動区間:

- プロセス開始
- 設定読込終了
- CSV読込終了
- ERH読込終了
- ERB列挙終了
- ERB解析終了
- リソース準備終了
- タイトル表示
- 入力受付開始

主なマクロ区間・カウンタ:

- マクロ展開
- 入力受け渡し
- ERB実行
- 文字列生成
- 表示データ生成・追加
- 文字計測
- 再描画・OnPaint
- スクロール更新
- UIイベント処理
- 割当量、GC回数、ワーキングセット
- 入力数、ERB実行数、乱数呼出数、状態・表示ハッシュ

計測用オプション:

- `--BenchmarkLog <path>`
- `--StartupTest`

## 5. 実測結果

環境やランダム戦闘内容で揺れるため、数値はこのPC・このセーブでの参考値である。

### 起動

- 最終通常版3回: 成功 3/3、警告Lv2 0件
- 内部初期化時間: 平均 4,230 ms
- ERB区間: 平均 2,777 ms
- テストハーネス上のプロセス壁時計: 平均 約6,359 ms
- Rename高速経路の公平比較: 4,720.0 ms → 4,557.3 ms、162.7 ms短縮（3.4%）
- 競合修正後の警告安定性試験: 20/20成功、警告Lv2 0件

### マクロ

同じ `save219.sav` と `(H\e\nd\e\n)*1000` を使用した記録:

- 描画集約前: 122,255.930 ms / 122,499.586 ms、平均 122,377.758 ms
- 採用版: 50,562.330 ms
- 参考短縮率: 約58.7%

耐久試験 `(H\e\nd\e\n)*5000` の採用系ビルド:

- 313,963.790 ms
- 326,286.106 ms
- いずれもテスト終了時 `Responding=True`

最終通常版プレイヤーのスモーク試験 `(H\e\nd\e\n)*10`:

- 885.8 ms
- `Responding=True`
- 終了画面を画像で確認

異なる起動ではゲームの乱数シードと敵数が変わるため、状態ハッシュ同士をそのまま一致判定には使えない。互換性の最終確認は短いマクロの画面確認、実行経路の確認、長時間の応答性確認を組み合わせている。

## 6. 非採用事項

- 解析済みERB全体キャッシュ: 安定した総時間短縮が得られず不採用
- 起動直後の強制GC・LOH圧縮: メモリは減るが起動時間を増やすため通常版では無効
- マクロ中の全描画省略: 標準動作の互換性を損ねるため不採用
- ERB処理回数、文字列生成、表示行生成を省く高速化: ゲーム状態・表示互換性を損ねるため不採用
- 17～29番の試験的ホットパス変更: 安定した総時間改善がない、または回帰したため不採用
