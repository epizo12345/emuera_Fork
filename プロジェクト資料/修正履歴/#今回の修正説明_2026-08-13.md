# Macroハッシュ衝突による低頻度ERB誤解析

## 概要

起動時に極めて低頻度で、実際のERB行とは異なる関数名の引数エラー等が表示される問題があった。調査の結果、Macroの登録・検索に文字列のハッシュ値のみを使っていたことを、観測されたcross-name警告の根本原因と判断した。

## 観測された症状

- 起動時の低頻度Lv2警告として発生した。
- 再起動で消えることがある。毎回同じERBでは発生しない。
- 警告側の関数名が、実際に解析している行の名前と一致しない。
- 当初はParallel Parserのrace conditionも候補に見えた。

## 実例

1. 実際のERB行が `@SKILL_RANK_460, ARG = -1` であるのに、警告側で `@イベントフラグ` のような別の関数名が表示された。
2. 実際の `@SKILL_RANGE_ディープホール展開,ARG` に対して、警告は `関数"@ダンジョンフラグ"の引数のエラー:引数の書式が間違っています` となった。

## 調査経緯

1. 低頻度Lv2警告を発見し、Parallel Parserの並列実行を疑った。
2. Before / After、Parallel ON / OFF、複数起動を比較した。
3. FunctionLabelLineのNameとPositionを診断し、元のERB位置と別のLabelNameが組み合わさるcross-name状態を確認した。
4. Macro lookupを調べ、`Dictionary<int, DefineMacro>` がハッシュ値のみをkeyにしていることを発見した。
5. 文字列keyへ変更し、Final Compatibility Verificationと修正後のKojo 100 / 100起動で再発しないことを確認した。

## 根本原因

旧実装はMacro名の `string.GetHashCode(...)` 結果だけを使う `Dictionary<int, DefineMacro>` だった。異なる文字列AとBが同じhash値になると、Dictionaryは元の文字列を比較できず、Aの検索がBのDefineMacroを返す可能性がある。その結果、元のERB行のPositionに誤ったMacro展開先のLabelNameが付いたような警告になる。

## 旧実装

```csharp
Dictionary<int, DefineMacro> macroDic = [];
var hash = key.GetHashCode(StringComparison.OrdinalIgnoreCase /* または Ordinal */);
macroDic.Add(hash, mac);
macroDic.TryGetValue(hash, out var value);
```

## 修正内容

`IdentifierDictionary` のMacro辞書を文字列keyにし、既存の `Config.StrComper` をComparerとして利用する。登録と検索の両方でMacro名そのものを渡すため、Dictionary内部のhashが衝突してもStringComparerのEquality確認が行われ、別Macroを誤取得しない。実装近傍に、同じ問題を再導入しないための短いコメントを追加した。

## 再現性が低かった理由

文字列ハッシュの衝突自体が低頻度である。加えて、.NETの文字列hashはプロセス単位のランダム化等によって実行間で値が変わり得るため、ある起動では発生し、次の起動では消える、または別のERBで見えるという低再現性になり得る。これは実装構造と実測結果に基づく説明であり、全てのランダム性を断定するものではない。

## 互換性確認

- `IgnoreCase = true`: `Config.StrComper = StringComparer.OrdinalIgnoreCase` で既存の大文字・小文字無視を維持。PASS。
- `IgnoreCase = false`: `Config.StrComper = StringComparer.Ordinal` で大文字・小文字を区別。PASS。
- Duplicate Macro behavior: PASS。Normal Macro Expansion: PASS。
- Normal / Diagnostic Release Build: エラー0件。Normal Startup、Kojo Startup: PASS。

## 修正後の再現試験

修正後Diagnostic Kojoを100回実行し、StartupFailure = 0、Lv2 = 0であった。この結果はMacro Dictionary由来の同じcross-name警告が再発しなかったことを示すが、他の共有状態の関係を証明するものではない。

## 今後同様の症状が出た場合

警告名と実際のERB行が一致しない、再起動で消える、毎回異なるERBで発生する、別のMacro展開先のような名前が出る、といった症状が再発した場合は、まず `string.GetHashCode()`、`GetHashCode(StringComparison...)`、`Dictionary<int, ...>` を検索し、ハッシュ値だけを一意識別子としている実装がないか確認する。

## 残存リスク / 別Issue候補

今回の `IdentifierDictionary` Macro辞書は文字列key化済みで、同じhash collisionによる誤Macro取得は防止される。一方、他の場所でhash値のみを一意識別子としている実装が残っていれば、同種の障害は起こり得る。Parallel Warning調査で残った `VariableLocal.localVarTokens` のownership候補は別Issueであり、今回は変更していない。
