# 今回の修正説明（2026-08-22）

## Phase 13R28 SingleStrTerm empty-value sharing

### 背景

runtimeの文字列値返却で、空文字列`""`の`SingleStrTerm` wrapperが短命に繰り返し生成されていた。空文字の頻度とゲーム全体のplateau削減量は未測定のため、今回の採用根拠は空文字wrapper allocationのsource上の除去、semantics維持、focused確認、Release build、実ゲームsmokeとした。

### Static audit

- `SingleStrTerm`生成箇所、`.Str`、`is SingleStrTerm`、`ReferenceEquals`、reflection、`sValue`書換えをwhole-repo検索した。
- constructor後に内部文字列を書き換えるproduction経路はなく、`GetValue()`は従来どおり`this`を返す。
- `SingleStrTerm` instance identityを意味論として使うproduction経路はなく、共有によりERB semanticsは変わらない。
- `sValue`を`readonly`化した。`null`と空文字の意味は混同していない。

### 実装

`Runtime/Script/Statements/Expression/Term.cs`に空文字専用の`EmptyTerm`と`FromValue` factoryを追加した。`value != null && value.Length == 0`のときだけ共有し、`null`と非empty文字列は従来どおり個別instanceを生成する。Dictionary cache、任意文字列cache、string interning、poolingは採用していない。

runtime/value-wrapper経路として、`VariableTerm.GetValue`、`FunctionMethod.GetReturnValue`、UDF string fallback、`AExpression.GetValue`、`StrFormTerm`、formatted string function returnをfactoryへ移行した。parser/config/static ASTの直接constructorは広い一括置換を避けて維持した。

### focused test

Release DLLをreflectionで直接確認し、次をPASSとした。

- `FromValue("")` / `FromValue(string.Empty)`の同一instance共有
- 非empty値の正しさと独立instance
- `FromValue(null)`がempty singletonへ畳み込まれず、null同士も共有しないこと
- `.Str`、`GetValue()`、`ToString()`、`sValue readonly`
- nullの`ToString()`例外が従来どおりであること

### Build / smoke

- Release build: 0 errors / 35 existing warnings / new warning 0
- formal publish: Release / win-x64 / framework-dependent / self-contained false / PublishSingleFile true / EnablePerformanceMetrics false
- 口上有りfixtureでInputReady PASS、save219 PASS、`(H\\e\\nd\\e\\n)*100`のRepeatCount=100 smoke PASS（観測7,474ms）
- 既存macro harnessはsave画面で`Process.MainWindowHandle`だけを検索するためtimeoutした。process-wideのtop-level window検索による同等driverで検証を完了し、アプリ終了・例外はなかった。

### 採用状態

Phase 13R28として正式採用した。主効果は`SingleStrTerm`の空文字短命allocation、Gen0 pressure、GC work、runtime churnの削減可能性であり、空文字頻度に応じて効果量は変わる。任意文字列を保持しないため、cache自身による有意なretained memory増加は避けている。ゲーム全体のWorking SetやTask Manager plateauが直接大幅低下すると主張しない。
