# 今回の修正説明 — 元Emuera（1824+v24）との描画差異の修正

## 背景

元のEmuera 1824+v24（GDI+）と現行（Skia）を同じERBで実行し、画像関数の結果と文字描画のスクリーンショットを比べた。違いが見つかったもののうち、次の3点を直した。調査の方法・数値・見送った差異は`プロジェクト資料/調査履歴/09_元Emuera1824v24との差異調査.md`。

1. `GDRAWG`（カラーマトリクス付きを含む）の拡大縮小が、補間なし（最近傍）固定でギザギザになっていた（差異1）。
2. `GSETBRUSH`していない`GFILLRECTANGLE`が、不透明の黒で塗っていた（差異3）。元は背景色。
3. 通常の文字をドット絵で描くフォント（ＭＳ ゴシック18pxなど）の斜体（`FONTITALIC`、太字の斜体を含む）が、輪郭から滑らかに描かれてにじんでいた（差異9）。元は細くくっきり。

## 仕様

- `GDRAWG`の拡大縮小は、`GDRAWSPRITE`・`PRINT_IMG`と同じく設定の画像補間（`ImageSamplingOption`）に従う。元EmueraのGへの描画は設定によらず固定のbicubicだったが、.NET版は画像補間を設定で選べるため設定に従う方針とした。元と同じ見た目にしたい場合は設定でCubicを選ぶ（元との平均の差: 補間なし21.2、Linear 6.0、Cubic 1.3）。等倍の描画は変わらない。
- ブラシ未設定の`GFILLRECTANGLE`は、コンフィグの背景色で塗る。背景色が黒のゲームでは見た目は変わらない。
- 通常の文字がドット絵（アンチエイリアスなし）で描かれるフォントと大きさでは、斜体と太字の斜体もアンチエイリアスなしで描く。滑らかに描くフォント（メイリオなど）の斜体は従来どおり。

変更しない点:

- 太字（`FONTBOLD`、HTMLの`<b>`）は、GDIと線の量が同じ（99.6%）だったため変更しない。擬似太字を足すと153〜178%と太りすぎる（差異8）。
- ごく低いアルファの色を書くとRGBが失われる件（差異2）は、現行ゲームのERBに該当関数の使用がなく、直すには描画全体の保存形式の変更が必要なため見送った。
- 外部フォントの扱いは対象外。

## 実装

- `[Emuera改修:DRAW-07 2026-10-28]` `UI/Game/Image/GraphicsImage.cs`の`GFillRectangle`: ブラシがなければ`Config.BackColor`の色で塗る。
- `[Emuera改修:DRAW-08 2026-10-28]` 同`GDrawG`（カラーマトリクス付きも同じ）: `JSONConfig.SamplingOptions`を渡して描く。
- `[Emuera改修:DRAW-09 2026-10-28]` `UI/FontFactory.cs`: 斜体は書体を傾けて作る（ＭＳ ゴシック等に斜体の書体がないため）。傾けた文字は内蔵のドット絵ではなく輪郭から描かれるので、`ApplyItalic`で、通常の文字がドット絵で描かれる場合だけ`SKFontEdging.Alias`にする。判定（`RendersAsBitmap`）はフォント・大きさ・設定の組み合わせごとに1回、試し描きして中間の濃さが出るかで行い、結果をキャッシュする。太字はWindowsが普通の書体から擬似的に作る場合があり、試し描きに中間の濃さが混ざるため、判定は同じフォントの普通の太さの書体（`RegularTypefaceOf`）で行う。`UI/Game/ConsoleStyledString.cs`の補完書体も同じ処理を通す（元のフォントのEdgingを写さず、設定から付け直す）。

## 効果

- `GDRAWG`で拡大縮小した画像が、設定の補間で滑らかになる（黒白2pxを8pxへ拡大したR値: 修正前`0 0 0 0 255 255 255 255`、元`0 0 23 99 185 245 254 254`）。
- ＭＳ ゴシック18pxの斜体の線の量が、GDIの約129%（にじみ）から99.5%に、太字の斜体は96.4%になった。見た目もほぼ同じ。
- 判定はフォント・大きさごとに1回だけなので、描画のたびの処理は増えない。

## 検証

回帰試験に4件を追加した（92件→96件）。

- `DrawingDiffRegression.cs`
  - ブラシ未設定の`GFILLRECTANGLE`が、試験中に差し替えた背景色で塗られること
  - `GDRAWG`の拡大が、設定Linearでは中間色を含み（カラーマトリクス付きも）、設定Nearestでは補間しないこと
- `FontItalicRegression.cs`
  - ＭＳ ゴシック18pxの斜体・太字の斜体がアンチエイリアスなしで、GDIの`TextRenderer`との線の量の比が0.9〜1.1に入ること
  - メイリオの斜体はアンチエイリアスのままであること

フォントがない環境では、フォントの試験は「試験不可」として扱う（`Program.TestUnavailableException`）。

修正後: 回帰試験96/96 PASS。実ゲームの画面での確認はしていない。
