# 今回の修正説明（2026-08-21）

## Phase 13R14 TermStack storage最適化

### 背景

Phase 13R10〜R13で、ERB式解析時のTermStackについて、単一要素のために都度`Stack<object>`を確保している経路を確認した。R13ではServer GC / Workstation GCの双方で、同一条件の反復検証と通常・口上有りfixtureの回帰確認を実施した。

### 実装

`Runtime/Script/Statements/Expression/ExpressionParser.cs`のTermStackを、空状態・単一要素のinline storage・複数要素時の`Stack<object>`昇格で保持する形へ変更した。式の評価順、演算子処理、セーブ形式、GCポリシーは変更していない。Workstation GCの採用やGC設定変更も行っていない。

### 検証

- Server / Workstation各10回、合計40回の有効な反復を実施。
- Normal / 口上有りfixtureでInputReady到達、Lv2 warning 0。
- ScriptParse中の一時allocationはServerで251,430,450 bytes（9.60%）、Workstationで251,445,633 bytes（9.60%）削減。
- 起動速度について明確な回帰は確認されず、R13の判定はPASS。
- Release build、正式single-file publish、Normal / Kojo smokeを完了。

上記allocation値はScriptParse中の一時allocationについての測定であり、常駐Working Setやプレイ中のメモリplateau削減を意味しない。次の調査対象はretained/live/committed memoryの実測とする。

### 採用状態

Phase 13R14として正式採用し、正式配布版へ反映した。

## Phase 13R23 PrivateInt1D bounded reuse

### 背景

private dynamic 1D整数配列のtop-level呼出しでは、同じサイズの配列を毎回確保していました。既存の2D bounded reuseと同じく、保持量に上限を設けた再利用が可能です。

### 実装

`Runtime/Script/Statements/Variable/VariableToken.cs`の`PrivateInt1DVariableToken`に、最大32,768要素（256 KiB）までのspare配列を1個だけ保持するbounded reuseを追加しました。再利用前に`Array.Clear`し、default値がある場合は復元します。nested / recursive呼出しでは従来どおり新規配列を使って外側の値を保持し、32,768要素を超える配列は保持しません。

### 検証

- Release build 0 errors / 35 existing warnings / Candidate由来new warning 0。
- default値なしの再利用clear、default値復元、nested / recursive外側値復元、32,768要素境界をRelease DLLの最小focused確認でPASS。
- 既存fixtureでsave219ロード後のRepeatCount=100 macro smokeを完了。

### 採用状態

Phase 13R23として正式採用し、正式single-file配布版へ反映した。配布EXEは24,643,306 bytes、SHA-256は`F7E145FB01E574A94C27221BE3B370EACFB3A130B7B60BD220A93B18BC034191`。
