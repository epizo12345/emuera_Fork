2026-08-17の更新では、性能改善が一通り完了した後の保守作業として、repository cleanup / code cleanupをProductionへ反映した。

今回の主目的は、現在の動作に不要な資料・雛形・内部コードを減らし、今後の調査で「現役コード」と「過去の残骸」を区別しやすくすることである。ERB/ERHの構文、セーブデータ形式、ゲーム処理の仕様を変更するための更新ではない。

## Warning cleanup Phase 4

Phase 3C後に残っていた52件のwarningについて、件数だけを目的に一括修正せず、正常動作への影響が小さく静的に理由を説明できるものだけを3段階に分けて整理した。

### Phase 4A: 純粋cleanup

まず、実行結果を変えない範囲のwarningを整理した。

- `HTML_PRINT_ISLAND_CLEARArgument.Term` の未使用fieldを削除
- 文字列で記述されていた引数名を `nameof(...)` へ変更
- 冗長な `Substring` を同値のrange表記へ変更

この段階でwarningは52件から43件へ減少した。対象はCS0649 1件、CA1507 6件、CA1514 2件で、新規warningは0件だった。

### Phase 4B: 安全な構造整理

次に、既存実装との整合を取る小規模な構造整理を行った。

- `ConstImage.Dispose()` で、同系統の `GraphicsImage.Dispose()` と同様に `GC.SuppressFinalize(this)` を呼ぶよう統一
- `ErbLoader.printFunctionNotFoundWarning()` のprivate引数型を、実際のcallerが渡している `InstructionLine` へ狭めた

この段階でwarningは43件から41件へ減少した。対象はCA1816 1件、CA1859 1件で、新規warningは0件だった。

### Phase 4C: 例外診断の整理

最後に、`ArgumentOutOfRangeException` の生成時に正しい `paramName` を渡すよう整理した。

- `array` を検証する箇所では `nameof(array)`
- `imgName` を検証する箇所では `nameof(imgName)`

正常経路の処理は変わらないが、異常入力時の例外診断では対象引数名が明示される。

この段階でCA2208 4件が解消し、warningは41件から37件へ減少した。新規warningは0件だった。
